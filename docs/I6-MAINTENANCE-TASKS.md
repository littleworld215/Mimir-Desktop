# 维护任务与安全取消（G-06）

## 使用方法

1. 保存工作台内容，在“设置 → 科研空间”点击“备份与恢复”，确认“关闭工作台并进入维护”。取消确认则留在工作台。
2. 备份点击“备份该空间”，自检点击“运行自检”。恢复先打开“恢复为新空间…”，填写新名称，开始后通过系统窗口选择归档和不存在的新空间位置。
3. 文本归档/路径仅是系统窗口建议，执行使用原生返回的选择。取消系统窗口不创建恢复资料；目标已存在、源文件或父目录身份变化时拒绝继续。
4. 运行中可点击“取消备份／取消恢复／取消自检”。“已请求取消”表示信号已送达，还需等待安全点和资源收尾，并查看最终结果。
5. 提交阶段不能安全取消，请等待发布/登记。已发布的空间/归档不会被删除。

## 核心逻辑

任务ID由主进程生成，种类固定为backup/restore/doctor，当前进程保留最多20份完成状态。taskStatus和cancelTask只收 `{ taskId }`，不收路径；匿名请求和额外字段拒绝。取消只匹配当前任务，旧ID不能取消下一任务；状态可查询当前任务及保留的完成回执。旧服务直接调用保持兼容；生产restore每次经过原生选择。重启后旧任务ID失效，产物通过G05持久恢复记录识别。

读取流、目录、清单、历史附件块和阶段边界有协作安全点；来源摘要由单一文件句柄逐块读取并等待关闭，取消时不重复关闭文件描述符。单条同步SQLite原生操作不强杀，下一安全点响应。提交前同步禁取消。停止期间仍阻断关闭/退出及新维护写任务；只读doctor也占用执行位置，无写锁不追加审计。

恢复取消只核验和清理当前操作创建的暂存。清理、文件/数据库关闭、锁释放失败报告TASK_CLEANUP_FAILED或STAGING_CLEANUP_FAILED并保留资料；已发布目录不删，残锁仍按原规约确认，不按年龄/PID自动删除。缺身份或摘要的崩溃产物继续保守保留。

前端只接受本轮任务ID进度；迟到回执不能改写下一任务。按钮沿用宿主语义与键盘焦点；旧桥无新能力时解释降级。
