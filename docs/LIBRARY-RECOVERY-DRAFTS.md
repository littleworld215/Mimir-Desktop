# 文献编辑恢复草稿

本功能在当前科研空间内保护卡片自由笔记、标签原输入与阅读器待追加内容。它不会自动修改正式文献。2026-10-23六批源码及隔离目录包完成验证：完整2232通过/9既有跳过，类型/构建exit0，开发和包内各16/16零重试；末尾一次非作者静态复核3项Important已按反例修复，不称独立运行QA。日常安装仍276aba3，尚未更新本功能。

## 使用方法

1. 在文献卡片展开后编辑笔记或标签，或在阅读器点“添加”。暂停输入约500毫秒后开始暂存。看到“恢复草稿已暂存（尚未正式保存文献）”才表示本次暂存已确认。
2. 点“保存”才写入正式文献。离开页面、切换科研空间或关闭应用仍需保存或明确丢弃，暂存不代替正常离开保护。
3. 意外退出后，在同一空间的文献库点“恢复草稿”，或打开原文献对应编辑器。先查看原始基线、当前文献与恢复输入，再明确选择恢复到编辑器；从列表定位编辑器后，还须在编辑器里确认恢复。
4. 确认输入后正式保存，或明确丢弃。单独保存笔记不清除仍在编辑的标签；离开时可将笔记和标签组合为一次正式更新。

例如将原笔记清空也属于有效输入：恢复草稿保留空字符串，不用“是否为空”推断未编辑。标签只沿用英文逗号分隔规则；暂存保留空格等原输入，正式保存再整理标签。

## 冲突、失败与已保存提示

- 已有草稿不会被新输入自动覆盖；须明确恢复或丢弃后才启用该编辑会话的暂存。正式内容变化时只提供对照、复制和丢弃，不提供强制覆盖或自动合并。
- 编辑器打开时也核对原显示基线；若其他入口已更新文献，当前输入保留，暂存和普通保存都不能借用新基线覆盖它。先复制输入，正常取消编辑后重新进入文献库加载当前内容，再对照编辑。
- 正式保存失败后先读取该草稿的最新修订。确认正式内容仍可编辑后，可继续修改、重试或取消；提交结果已应用、冲突或无法读取时保留输入并要求对照，不猜测成功，也不再次追加。
- 取消和丢弃需要等待实际操作完成，期间禁用编辑及重复提交。空间或文献已经变化时，旧响应不能关闭、重置或清除新会话。
- 文献已回收或失联时，草稿仍可查看和复制，不自动恢复文献。文献回收预览列出关联编辑草稿数，回收与恢复均保留其原字节。
- 暂存不可用或超限时保留当前输入，可复制，或显式选择“不使用恢复保护保存当前修改”。这种普通保存不提供提交意图保障，也不清理已有恢复条目。
- 新的受保护保存须先写入准备意图；准备失败时不会继续写正式内容或自动退回普通保存。
- “文献已保存，草稿清理失败”表示正式保存已经成功。重启后若正式内容与意图结果相同，只清理残留即可，不再次追加。若正式内容仍等于基线，可恢复后重试；其他内容视为冲突。
- 丢弃失败时仍留在当前页面，输入保留。不要通过强制结束日常应用来测试本功能。

## 存储与核心逻辑

固定路径为科研空间内 `.mimir/library-editing/drafts.json`，格式版本1。最多1000条，单条序列化2MiB，整体32MiB，按UTF-8字节计算；超限拒绝本次暂存，不截断、不自动淘汰。正式笔记的原合法范围不因此收紧。

主进程签发会话，绑定可信窗口、空间ID、代际、固定根和文献。暂存带递增序列与修订，文件按同目录临时写入、同步、关闭、重新校验再原子发布；拒绝链接、损坏、新版本和来源变化。接口没有任意路径参数。退出与维护等待已接受任务实际收口。

正式保存先持久化确切结果及提交标识，再核对基线并调用原文献更新，最后清理相应草稿。追加时间戳及结果在意图中固定。文献与草稿是两个文件，不声称跨文件原子事务，也不提供跨进程或任意第三方写者的一致性保证。

## 备份、恢复和自检

整空间备份收入草稿原文件。恢复发布前校验结构、容量及关联；旧备份缺文件合法，损坏或较新格式阻断发布。恢复到新UUID后重新签发会话，旧根/代际令牌不能写入新空间；草稿正文和意图中的路径原样保留。

维护自检只显示数量、未解析关联和错误码，不输出草稿正文。发现损坏时保留原文件，不自动重置。草稿不隐式混入正式文献的JSON或BibTeX导出。

## 已知边界与后续

- 500毫秒是触发防抖，未发送或尚未确认落盘的字符无法保证在强制结束后恢复。
- 当前是本机个人空间内的恢复机制，不是多人实时协作或自动同步冲突解决。多个设备同时修改空间仍须遵守单写者约定。
- 初版不自动清理孤立或历史草稿；清理须由用户明确操作。保存失败及清理失败分别提示。
- 日常安装更新、真实课题使用及I5/I6其他待验独立登记，不由此文档或作者测试自动宣布完成。
