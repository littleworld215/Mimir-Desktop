## 核心逻辑

1. 在创建输出前确认暂存和目标位于来源之外，包括解析已有祖先junction。固定真实输出目录及身份，在快照、写包、验包和发布边界重新校验。
2. 流式观察来源实际文件集合、身份、大小、修改时间及SHA256；主库/WAL/journal按实际来源观察，包内仍用SQLite一致快照，SHM/运行锁/未提交staging保持原排除。观察结束同步复核目录子项及已经读过的文件，避免遍历途中新增或回头修改被漏过。
3. 写唯一临时ZIP；显式拥有yazl惰性读流，写入失败停止新来源、销毁活动流并等实际关闭，再清理。同步并关闭临时包后，独立重新打开验包；两轮验包均等待真实关闭及关闭错误。
4. 验包后重新观察来源；发布前再检查输出位置及临时包身份/大小/时间。通过后用同卷硬链接原子、不覆盖地发布，再移除临时名字。晚到目标保留原字节；不以可覆盖rename或可见半包复制降级。

格式仍为1，旧导入/导出接口不变。`archiveFormat.ts`集中格式常量，避免打包与独立验包的运行时循环；旧packer导出继续保留。锁定yazl3.3.1的惰性方法采用局部类型补足，未安装新依赖；yauzl3.4.0底层关闭失败的reader事件有实际故障回归约束。

正常关闭后的WAL库以只读句柄重新打开时，SQLite可能延迟创建空旁文件。来源基线前先作只读schema_version查询完成初始化，快照仍在基线之后；不会忽略后续真实WAL提交，也不迁移或改写源主库。

## 使用与限制

仍使用“设置 → 备份与恢复”离线入口，不增加自动后台备份。备份失败先保留来源并查看错误；不可把未发布的`.partial`当作完成包，不按时间自动删除科研空间锁。

- 来源变化或无法读取、临时包损坏/变化、同步/关闭失败、目录改向或目标已存在均不能返回成功备份。
- 发布要求暂存与目标同卷，且文件系统支持硬链接；不支持的卷会明确失败。首版运行验收限Windows x64本机NTFS，不推断FAT/exFAT/网络盘已支持。
- 现有>1GiB单文件排除继续保留，排除项仍只比较身份/大小/时间，不额外读取大文件。备份有排除项时不能称全部收录。
- 增加来源流式复核与独立验包，代价是额外磁盘读取；不缓存整文件。普通文件API不能提供VSS级快照，也不能排除最终同步复核之后第三方瞬时修改。
- 归档读取上限G-02、旧DB迁移/托管关联、更多路径与快照关联、取消及崩溃注册重试等仍按原矩阵推进；外置登记仍暂不实施。
