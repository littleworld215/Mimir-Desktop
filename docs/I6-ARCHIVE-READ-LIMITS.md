# 归档读取上限与严格校验（G-02）

2026-10-24。承接[G-01备份一致性](I6-BACKUP-CONSISTENCY.md)，对应来源[I6矩阵G-02](https://github.com/littleworld215/research-asset-library/blob/main/docs/I6-ACCEPTANCE-MATRIX.md)。本批补读取边界，不代表I6整体终验或日常安装已升级。

## 读取规则

- 默认最多100000个ZIP条目，包含清单自身，沿用旧验包计数。清单实际展开最多64MiB；业务文件实际展开合计最多1TiB。清单有独立预算，不再计入业务合计；目录必须声明0字节。
- ZIP中央目录先限额，读取流中再按实际字节扣预算；不能通过缩小ZIP自报大小绕过。内容超过剩余预算时不再交给哈希或写盘。
- 清单必须是格式1对象，entries为数组；路径/kind/非负安全整数size/SHA256字段严格校验。目录摘要为空，文件摘要为64位小写十六进制。已知来源/生成时间字段检查类型，未知业务键保留；早期缺sourceRoot合法，不猜填。
- 路径大小写冲突、重复条目、文件目录类型冲突、清单集合不一致、链接/设备类型、加密或不支持的压缩方式均拒绝。清单本身不能作为业务文件声明。
- 每遍独立计数并核对集合，单卷ZIP/ZIP64的中央目录字节范围与实际消费位置必须一致，不能用依赖库end掩盖少报条目。第二遍仍读取并限制清单；清单缺失或改变不能沿用首遍结果放行。
- 目录实际流也验证为空，合法deflate空流保留。失败等待受管管线和实际归档关闭；取得源流后才创建写盘目标，避免等待源打开时写盘错误先于监听。

## 三个入口

1. `verifyBackup`：限流读取清单、核对目录和声明，再逐文件流式验证实际字节和摘要。
2. `readArchiveManifest`：恢复预览只扫描元数据和清单，不读取所有业务内容；它不是完整验包成功凭据。找到清单后继续扫描目录，不能放过晚到重复或超限条目。
3. `extractToStaging`：即使调用方做过预验，解压本身仍执行限额、清单和集合校验，在交出数据前扣预算；失败不发布新空间，原空间和注册表保留。

格式1和旧`verifyBackup(path, maxEntries)`继续兼容。主进程内部可注入更小预算作回归，不能提高生产上限；未增加渲染桥、用户设置或依赖。错误码新增`MANIFEST_LIMIT`、`TOTAL_LIMIT`、`LIMIT_INVALID`，恢复编排保留明确拒绝原因。

## 使用及验收边界

仍从“设置 → 备份与恢复”进入离线维护。遇到超限或损坏包应保留原包和原空间，先检查报告；不要将暂存目录当作恢复完成。现有备份侧>1GiB单文件排除未改变，读取上限不等于取消该排除。

本批只用合成文件，使用小预算及受控ZIP字段验证边界，不制造TB文件、不占满用户磁盘。实际旧包反例、最终工程闸门和新目录包结果见[本轮验证](https://github.com/littleworld215/research-asset-library/blob/main/docs/verification-archive-read-limits-20261024.md)。作者运行、一次非作者静态复核和独立运行QA分别记录；日常6645129安装、真实资料与原I5/I6其它待验保持。
