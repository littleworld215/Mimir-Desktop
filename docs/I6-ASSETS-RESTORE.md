# 资产库恢复兼容与历史附件（G-03）

2026-10-24。承接[I6交付](I6-DELIVERY.md)及来源[G-03判据](https://github.com/littleworld215/research-asset-library/blob/main/docs/I6-ACCEPTANCE-MATRIX.md)。这批增强新空间恢复校验，不自动更新日常安装，也不代表I6全范围验收结束。

## 恢复规则

1. 归档先执行现有摘要、路径和[读取限额](I6-ARCHIVE-READ-LIMITS.md)检查，再解压至持锁的同卷暂存目录。
2. `.mimir/assets/assets.db` 存在时，按资产域当前版本4检查完整结构、索引、约束、触发器、全文结构和外键。较新或非法版本返回 `VERSION_UNSUPPORTED`；损坏或漂移结构返回 `INTEGRITY_FAILED`。不凭表名齐全猜测兼容。
3. 只支持既有迁移器定义的版本：0仅限真正空库，1/2/3必须精确匹配当时结构。先验证全部历史附件，再在暂存资产目录的 `backups/` 创建独立SQLite一致快照，成功后才迁移暂存库至4并复核。当前4不迁移、不额外生成快照。
4. 任何历史版本的非NULL `file_path` 都要检查，包括已归档资产、非当前版本和回滚复用。文件必须是所属资产 `files/<asset_id>/` 内的普通文件，以64KiB缓冲分块读至EOF，并核对实际字节和前后状态；同一路径复用只读取一次。穿越、设备名、ADS、跨资产目录、链接/悬垂链接、目录伪文件、缺失、读取EIO或提前EOF均阻断发布。兼容Unicode、旧反斜杠路径和NULL无附件；不删除未引用资料或修改历史正文。额外完整读取增加磁盘I/O，不把整文件装入内存。
5. 校验完成后才沿现有恢复流程发布新目录、追加新空间记录。失败不发布本次新空间、不追加注册；原空间和归档不迁移、不改写。迁移失败保留的暂存资料按原恢复结果显示，不擅自清理其它内容。

SQLite一致快照保留旧结构及已提交内容，页头计数可不同，不承诺与原数据库物理字节相同。对原空间和原归档则继续核对逐文件摘要不变。历史附件没有独立数据库摘要字段：本检查证明关联、归属与可读，包内内容摘要由归档校验负责，不将其表述为附件语义正确性证明。

## 自检与使用

仍从“设置 → 备份与恢复”进入离线维护界面。在新空间恢复失败时先查看错误码并保留原包，不用删除附件或改版本号来绕过检查。旧库只有在新空间的恢复暂存副本迁移，源空间继续可回退。

只读自检现定位真实 `.mimir/assets/assets.db`，与恢复共用版本/结构/全部历史附件检查。未启用资产模块的现存普通空间合法；空间根缺失、非法目录和悬垂路径不能冒充空库。自检不迁移、不创建缺失数据库；开发及目录包显式使用各自原生绑定。SQLite只读连接可能生成空WAL/SHM协调文件，因此“只读”不等于绝无文件系统副作用。
