# 恢复中断后的登记与清理（G-05）

2026-10-25。承接[I6交付](I6-DELIVERY.md)、[恢复关联](I6-RESTORE-ASSOCIATIONS.md)及来源[G-05判据](https://github.com/littleworld215/research-asset-library/blob/main/docs/I6-ACCEPTANCE-MATRIX.md)。本批源码增加恢复记录和维护界面，安装版更新另行登记；完整结果见[本轮证据](https://github.com/littleworld215/research-asset-library/blob/main/docs/verification-restore-recovery-20261025.md)。

## 如何使用

在包含本批功能的构建中，保存工作后从“设置 → 备份与恢复”进入维护。页面新增“中断恢复与登记”，列出操作名称、日期、阶段状态和条目数。

- **已发布，待复核登记**：点击“复核并完成登记”。只读复核原目录后，以该操作原有UUID登记，不重新解压、不另造空间；保留原active/default和其它设置。
- **暂存已保留**：点击“核对并清理暂存…”。主进程弹出确认框，默认“保留暂存”；确认后还会核对目录身份、完整内容摘要、空间锁原凭据及资产锁状态。核对失败保留资料和现有锁。
- **已登记／暂存已清理**：已有结果保留在列表。重复登记只在相同ID、相同目录且资料核对通过时幂等，不重复追加或生成无用快照。
- **缺少摘要、身份或登记变化、损坏记录**：保留现场并显示人工检查提示。创建后身份尚未落盘、摘要未完成及删除途中失败，不猜测修复。
- **维护写锁未取得**：只能查看记录和运行不落审计的自检。请按现有锁处理规约确认并处理残锁，再重新进入维护；没有按年龄或PID移除锁的行为。

每页最多读取50份记录，使用“下一页恢复记录”继续、“返回恢复记录首页”回到开头。按稳定操作标识分段，同页按更新时间展示；不是全库按日期倒序。完成记录不会挤掉旧待处理记录的入口，超过1000份也可继续翻页。重新读取不会执行写入。

已发布的新空间不提供删除按钮。早期版本没有操作记录的暂存不会被按目录前缀纳入清理；需按既有人工流程核查。

## 核心逻辑与存储

`restoreJournal.ts` 将每次操作的固定UUID、目标／暂存位置、父目录和创建根身份、阶段、数量、摘要写到本机profile对应的 `.mimir/restore-operations/<操作ID>.json`。这是私有恢复元数据，不是业务资料导入格式，不包含正文、模型设置或账户凭据，也不替代逐事件审计历史。单份64KiB上限，严格校验版本和字段；写唯一临时文件、同步并关闭，再原子发布。旧档、损坏或较新记录不会被重置为空。

`restoreRecovery.ts` 装饰现有恢复步骤，在副作用前后记账；固定同一个新空间ID与暂存token。目录rename成功但记录尚未更新时，重启根据同一创建根身份识别已发布位置；登记已落盘而完成记录失败时，以注册表中ID和路径同时匹配识别结果。任一冲突均拒绝，不能用“路径相同”冒充另一UUID的登记成功。

`restoreFingerprint.ts` 按64KiB块读取内容，包含目录及隐藏资料，最多10万核对条目、1TiB字节；不把整文件放入内存。排除的受管活锁在异步复核后和同步提交边界单独检查。拒绝已替换目录、链接、内容或集合变化。恢复后的资产库只读复检，不在已发布目录重新迁移。

共享桥只接受操作ID、固定动作和主进程产生的分页游标，路径从记录解析。只信任维护主窗口主框架；备份、恢复、登记、暂存清理和备份保留删除共用维护写互斥。任务未完成时阻止关闭交接；普通业务的控制闸门不嵌套调用。

## 失败与兼容边界

- 归档格式仍1，资产库schema仍4；没有新依赖。现有恢复接口保留，新桥可选，旧界面／旧主进程按缺省降级。
- 强退可能留下写锁，产品仅只读识别。自动化测试在确认其自身合成主进程退出、锁凭据和摘要匹配后隔离测试锁；这不是产品自动解锁，也不是对真实残锁的操作授权。
- 文件同步与原子替换不等于断电后的全链路目录持久性。未知重解析点、最终同步核验间的任意第三方瞬时替换、网络共享和跨机器同步不扩大保证。
- G-06完整取消／原生路径授权、G-07元数据和Windows ACL、G-08综合异常、I5/I6/I10整体及真实资料验收继续单列。
- 本批只使用合成资料，未调用模型或做科研实验，日常安装、profile、科研空间和快捷方式未改。
